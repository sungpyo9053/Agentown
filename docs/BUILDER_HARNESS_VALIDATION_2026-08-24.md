# Builder 표준 하네스 검증 및 배포 게이트

## 최종 게이트

운영 배포에는 다음 조건을 모두 요구한다.

1. 100개 완전 명세 업무 중 80개 이상이 실제 Codex 구조화 출력, 서버 스키마/그래프 검증, 표준 폴더 생성, 노드 시뮬레이션을 통과한다.
2. 글쓰기, 뉴스 분석 보고서, 고객 문의, 분류/판정, 승인 대기·재개 핵심 경로가 모두 통과한다.
3. 보안, 외부 쓰기 승인, 워크스페이스 격리, 상태 전이, 중복 실행에 치명적 결함이 없다.
4. 회사 가져오기에서 Agent Definition 수만큼 영속 Agent 직원이 생성되고 팀/부서에 배치된다.
5. 기존 회귀 테스트와 운영 E2E가 통과한다.

80%는 하한선일 뿐이며, 나머지 조건 하나라도 실패하면 배포하지 않는다.

## 100건 결과

- 모델: `gpt-5.6-luna`
- 실제 실행형 표준 폴더: 92/100
- 최초 실패: 그래프 검증 7건, Codex 제한시간 초과 1건
- 표준 폴더: `AGENTS.md`, `CODEX.md`, `workflow.json`, `design-bundle.json`, `manifest.json`, `agents/*.md`, `guides/*.md`

## 실패 원인과 수정

- 단일 분기 `success` 엣지는 분기식 필드를 식별할 수 있을 때만 `field=true`로 정규화한다.
- 분류 업무의 `분석` 표현은 별도 생성 단계로 과잉 판정하지 않고, 명시적 생성 표현만 검사한다.
- 정상 비자기 출구가 함께 있는 중복 자기 엣지만 제거한다. 유일한 자기 엣지는 계속 검증 실패한다.
- Codex 제한시간 초과는 검증을 우회하지 않고 동일 TC로 재실행한다.

수정 후 최초 실패군 8건을 다시 실행했고 모두 실제 패키지 생성까지 통과했다.

## 회사 가져오기 계약

- 활성화 전에 현재 Workflow Version의 성공한 시뮬레이션과 완전한 표준 폴더를 요구한다.
- 동일 Workflow Version 재요청은 같은 팀을 반환해 직원 중복 생성을 막는다.
- 각 Agent Definition을 기존 `AgentService`의 PRIVATE Agent로 저장한다.
- Agent/Guide Markdown을 기존 Agent Definition과 팀원 스냅샷에 저장한다.
- `업무 자동화 > <업무명> 팀 > 실제 직원` 구조를 내 회사에 표시한다.
- 다른 workspace 사용자는 팀과 직원을 조회할 수 없다.
